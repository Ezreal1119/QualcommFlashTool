Firmware: `SQ53ST_EN_XX_WE__DS__R01_U_250827_02_rel_modem_2.2_PRO.zip`, explicitly chosen by the user. A new working directory was extracted without modifying the original archive or previously edited packages. Programmer: `prog_firehose_qcm4290_ddr.elf`.

## Observations

- The previous initializer consumed only four startup packets and left all 15 advertised Firehose functions queued. Reading the remaining startup packets allowed NOP and configure to succeed immediately.
- The programmer explicitly reported UFS, Micron `MT064GASAO2U21`, 4096-byte blocks and six active LUNs. Reported block counts: 0=14499840, 1=2048, 2=2048, 3=32768, 4=1048576, 5=32768.
- Offline validation found 66 image operations and 78 ordered DISK patches, with 5,034,967,040 transfer bytes. All write ranges fit the reported geometry. The plan retains and displays shorter-image allocation notes and equivalent host-file patches.
- Before flashing, all six existing primary/backup GPTs and CRCs were read and validated, and a boot_a SHA-256 digest was obtained from the programmer.
- Live flash task `20261112-221106-396fe4`: all 66 image operations and 78 patches completed. The write, patch, verification and reset-command session took 130.5 seconds.
- Final verification passed: primary/backup GPT headers and partition arrays with CRCs on LUNs 0–5, plus SHA-256 digests for vbmeta_system_a, vbmeta_system_b, boot_a, vbmeta_a, boot_b and vbmeta_b. No unavailable checks were reported. These are the default verification targets, not a digest of every flashed image.
- The reset command was acknowledged, but the old implementation closed USB before consuming two trailing reset logs. A read-only diagnostic drain received `Will issue reset/power off...` and `bsp_target_reset() 0`; USB then disappeared. The corrected reset handler drains these logs and requires EDL disappearance before reporting reboot completion.
- On 2026-11-13 (Asia/Shanghai), the user confirmed the device had entered Android. Startup is confirmed by the user's screen observation, not by an ADB boot-completed query. This completes the observed write, verification, reset and Android-startup sequence for this device and firmware combination.
- A cold Sahara upload with the new packet-safe transport has not yet been repeated; the live run reconnected to the already-uploaded programmer. This record does not establish compatibility with other devices.
